## 5. アーキテクチャ

### コンポーネント構成

| コンポーネント | 役割 | 主な機能 |
|---|---|---|
| Builder | インストーラーの生成 | 設定読み込み・配布ファイルの取り込み・生成 |
| Installer Runtime | 生成されたインストーラーの実行 | 起動・GUIとCoreの連携・終了処理 |
| Installer Core | インストール処理 | ファイル配置・進捗管理・エラー処理 |
| GUI Layer | ユーザーインターフェース | 画面描画・レイアウト・テーマ・入力 |
| Platform Layer | OS固有処理の抽象化 | PATH・ディレクトリ・権限・OSへの登録 |

### 設計原則

| 原則 | 方針 |
|---|---|
| 疎結合 | GUIとInstaller Coreを分離する |
| 移植性 | OS依存コードをPlatform Layerに集約する |
| 拡張性 | 将来的な機能追加やGUIの交換を可能にする |
| 汎用性 | Cerune固有の処理をLilIns本体に組み込まない |
| カスタマイズ性 | 外観や操作フローを設定から変更できる構成を目指す |
| 安全性 | インストール先の検証・エラー処理・復旧を考慮する |
| 可読性 | 複雑な抽象化を避け、理解しやすい実装を優先する |
| 独立性 | BuilderとRuntimeを分離し、不要な実行時依存を避ける |

## 6. 機能設計

| 機能 | 内容 | 優先度 |
|---|---|---|
| GUIウィンドウ | インストーラー画面の表示 | 必須 |
| 基本ウィジェット | ボタン・テキスト・進捗表示 | 必須 |
| ファイル配置 | 指定先へのファイルインストール | 必須 |
| インストール先選択 | ユーザーによる保存先指定 | 必須 |
| 進捗・エラー表示 | 処理状況の表示 | 必須 |
| 設定ファイル | インストーラーの構成定義 | 必須 |
| テーマ | 色・フォント・外観の変更 | 必須 |
| オフライン配布 | ネット接続なしでのインストール | 必須 |
| アンインストール | インストール済みファイルの削除 | 必須 |
| PATH設定 | コマンド実行環境への登録 | 必須 |
| アップデート | 既存バージョンの更新 | 中 |
| 失敗時の復旧 | 中断・失敗時のロールバック | 中 |
| OSへのアプリ登録 | Windowsなどのアプリ一覧への登録 | 中 |
| GUIアニメーション | 画面遷移・視覚効果 | 低 |
| プラグイン機能 | 外部拡張機能 | 低 |

※ 優先度は実装順の目安です。

## 7. 開発フェーズ

| フェーズ | 目標 | 完了条件 |
|---|---|---|
| 0. Bootstrap | C17・CMakeの開発基盤 | 最小プログラムがビルドできる |
| 1. Window | SDL3の導入 | ウィンドウが表示される |
| 2. GUI | 基本UIの構築 | ボタン操作と画面描画ができる |
| 3. Core | ファイル配置処理 | テスト用ファイルを安全に配置できる |
| 4. Integration | GUIとCoreの統合 | GUIからインストール操作を実行できる |
| 5. Builder | インストーラー生成 | 設定と配布ファイルから実行形式を作れる |
| 6. Portability | OS間の移植性検証 | 対象OSでビルド・基本動作を検証できる |
| 7. Release | 初期公開 | ドキュメント・テスト・成果物を整備する |
